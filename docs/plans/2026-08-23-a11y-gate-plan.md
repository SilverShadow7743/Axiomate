# The accessibility gate — implementation plan

**Design:** `2026-08-23-a11y-gate-design.md` · **Date:** 2026-08-23

Ordering: the gate installed and run BEFORE any fix, so the first run's findings are the
work list rather than a guess; then the fixes; then the deploy only if a fix touched a
shipped surface.

## Steps

**1. Install + config + first run — `package.json`, `eslint.config.mjs` (new).**
`npm i -D eslint eslint-plugin-jsx-a11y @typescript-eslint/parser`; flat config scoped to
`components/**/*.tsx` and `app/**/*.tsx` with ONLY the jsx-a11y recommended rules;
`"audit:a11y": "eslint ."` script. Run it and RECORD the findings count before touching
anything.
*Verify:* `npm run audit:a11y` runs and reports; the count is written into the step-2
commit message.

**2. The fixes — whatever step 1 names.
THE STEP CARRYING THE MOST REGRESSION RISK** — accessibility fixes touch live interaction
paths (a div becoming a button changes focus and submit behaviour; a keyboard handler
added wrong fires twice). Each fix keeps the existing pointer behaviour byte-for-byte and
adds the keyboard path. A rule downgraded instead of fixed carries a comment naming the
rule, the surface, and the reason — never a bare `off`.
*Verify:* `npm run audit:a11y` exits 0; `npx tsc --noEmit && npm run build`;
`npm run validate:scenarios` parsed 0 FAIL (the suite catches a reducer-visible behaviour
change; screen-only changes it cannot see are why the fixes keep pointer behaviour
untouched).

**3. Sweep, deploy (if any component changed), checklist section 31, push.**
The checklist section carries the gate's command AND the manual keyboard walk the static
gate cannot do: tab through the grid, the detail panel, one modal (Escape contract), the
Inbox; note contrast spot-checks. Clean-room release → deploy → health → push.

## Details most likely to be got wrong

- **Pointer behaviour stays byte-for-byte** — fixes ADD the keyboard path; changing a div
  to a button inside a form silently becomes a submit button (`type="button"` always).
- **`eslint.config.mjs` scopes to the two directories** — linting `lib/` or `scripts/`
  drags non-JSX files into a JSX ruleset for nothing.
- **Downgrades carry reasons in the config** — the design forbids bare `off`.
- **FAIL gates parse JSON** — python, utf-8 stdout, for the suite half.

## Commits

Step 1 alone (the gate and its honest first count). Step 2 alone. Step 3 with the
checklist.

## What would send the design back

- Dozens of justified downgrades — the gate is theatre; replace with a browser-driven
  audit instead of accumulating exceptions.
